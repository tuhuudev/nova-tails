# NOVA TAILS — Master Architecture v0.1

**Status:** REVIEW — proposed until Phase 0 is accepted.  
**Purpose:** Define durable boundaries and dependency principles before detailed product/content production. Product identity, concrete game/lore taxonomies and output priorities remain hypotheses until dedicated reviews.

## 1. Architecture model

Current Product Vision hypothesis is a distinctive multi-species sci-fi/fantasy universe/IP intended to become original, initially explored through character-centric concepts and potentially supporting multiple adaptations. Phase 0 does **not** approve that market/product hypothesis; it proposes how accepted canon and adaptations should relate if retained.

```text
                 PROJECT / IP (working name)
                         |
                    ACCEPTED CANON
                         |
          +--------------+--------------+
          |              |              |
        WORLD        IDENTITY        SYSTEMS
                         |
              MASTER ENTITY/CHARACTER IDENTITY
                         |
              ADAPTATIONS (optional)
             /          |          \
           GAME         2D          3D
```

No adaptation lane is automatically required to be a launch product. Product Vision decides priorities. Generated images/models are outputs, not source of truth. Originality/third-party-rights risk requires validation; it is not guaranteed by AI generation or this architecture.

## 2. Proposed canon layers

### Universe Canon
Accepted cosmology/history/world/faction/culture/conflict/terminology when those systems exist.

### Identity / Character Canon
Accepted stable identities and retained constraints.

### Game Canon — conditional
Interaction/combat/progression/abilities/stats/equipment/enemies/economy/acquisition only if the game direction retains them and they survive review/prototype.

### Asset Canon
Accepted visual/output standards. Manufacturing constraints become canonical only if physical collectibles remain in scope and are physically tested.

## 3. Candidate character architecture — DRAFT

Potential dimensions include origin, world identity, combat identity if applicable, progression if applicable, visual DNA and output adaptations. This is a stress-test model, not approved taxonomy. Candidate terms/lists previously explored remain DRAFT.

## 4. Proposed taxonomy principle

Avoid unnecessary coupling. Do not mass-populate candidate taxonomies before product/prototype review.

## 5. Proposed progression/equipment principle

If progression/equipment exists, each retained system should create a distinct decision/unlock/job. Systems that only duplicate percentage stat inflation should be merged/removed. Existing progression/equipment models remain DRAFT.

## 6. Proposed interaction-data principle

Do not design exhaustive ability/stat schemas before a working prototype exposes actual behavior/data needs. Existing ability vocabularies remain candidate ideas only.

## 7. Proposed encounter principle — conditional

If the product/game uses enemies/bosses, they should teach/test mechanics and belong coherently to the world rather than functioning only as HP/stat bags.

## 8. Proposed stable identity principle

Production identities should receive stable IDs once taxonomy/registry/tooling demonstrates the need. ID format should be selected from real namespace/query/migration requirements rather than locked during Phase 0.

If forms/evolution remain part of the product, forms should inherit base identity rather than independently redefining it. Exact schema is deferred.

## 9. Proposed cross-output identity principle

If multiple outputs are retained, adaptations may differ technically while preserving accepted identity. If print is retained, visual effects/fine details may require physical reinterpretation; such examples are not manufacturing specifications.

## 10. Proposed AI generation architecture

```text
ACCEPTED CANON
  ↓
Context Builder
  ↓
Prompt Template
  ↓
AI Proposal
  ↓
Validation
  ↓
Human Review
  ↓
Approved Canon / Asset Registry (when applicable)
```

Prompts are derived artifacts. Prompt text must never silently override canon.

## 11. Proposed validation gates

Use only gates relevant to the artifact/system being reviewed: identity consistency; world/game constraints; visual distinction; physical tests when print is retained; IP/name/design research/provenance/human review where relevant.

These processes reduce risk; they do not guarantee absence of third-party rights.

## 12. Proposed production principle

Do not expand content simply because AI makes content cheap. Production begins only after a representative end-to-end proof validates retained product assumptions and required pipelines.

## Phase 0 review boundary

Accepting Phase 0 would approve the **architecture/governance principles**, not the proposed universe positioning, game format, world lore, taxonomy, ID format or physical-product role. Product Vision and subsequent evidence/prototypes decide those.
