# P04 / P05 — Preproduction Validation Plan v0.1

Status: PLANNED — NO PRODUCTION ASSETS REQUIRED YET
Date: 2026-09-16

## Why these tests happen before implementation
NOVA TAILS currently has directional evidence that upgrading/combination may be interesting. Before building evolution production assets or a combination engine, test whether people understand and value the mechanics.

---

## P04 — Evolution Comprehension

### Question
Can a respondent perceive Stage 1 -> Stage 2 -> Stage 3 as the same character becoming more developed, rather than three unrelated creatures?

### Required input
Three LOW-COST candidate silhouettes/concepts only. Do not build final 3D, lore, skills, stats, or production sheets for P04.

### Design constraints
Stage progression hypothesis:
- Stage 1: cute / compact
- Stage 2: adventurous / balanced
- Stage 3: powerful

Candidate evolution should preserve the current prototype identity anchors sufficiently to test inheritance:
- EAR_SHAPE
- FOREHEAD_MARK
- TAIL_SPLIT

### Questions
1. Put these three forms in the order you think they belong.
2. Do they look like the same creature evolving? Why/why not?
3. What features make them feel related?
4. What changed the most?
5. What should never change across evolution?
6. At which transition does it start to feel like a different creature, if any?

### Gate
Do not promote Stage 2/3 to production because one design is visually impressive. Promote only after the family relationship is understandable and the inherited identity rules survive.

## P05 — Combination Interest

### Question
Is combination a meaningful collectible/play mechanic, and what inheritance behavior does a user expect?

### Test conditions
Present the idea at concept/rule level. Avoid expensive combined-character production.

A — Evolution only
A character upgrades through its own stages.

B — Combination only
Two compatible characters can create/unlock a new form that inherits traits.

C — Evolution + Combination
Characters evolve individually and selected evolved/base forms can participate in combinations.

### Questions
1. Which system would you most want to experiment with?
2. What would you expect a combined character to inherit from Parent A?
3. What would you expect it to inherit from Parent B?
4. Should combination be predictable, partially surprising, or highly random?
5. What would make a result feel unfair or meaningless?
6. Would you try combinations mainly to discover appearances, gain gameplay utility, complete a collection, or something else?
7. Should every pair combine, or only compatible pairs?
8. Should the result be reversible?

### Hypotheses to test
- Players value visible inheritance over random AI novelty.
- Some surprise is desirable, but identity needs rules.
- Combination may create collectible depth only if results have understandable provenance.
- Compatibility constraints may make the system more legible and controllable than universal pairwise combination.

### Do not implement yet
- combinatorial asset generation at scale
- rarity/economy
- breeding probabilities
- monetization
- blockchain/NFT mechanics
- final stat inheritance
- final fusion/evolution lore

These require product evidence and game/economy decisions not yet available.
