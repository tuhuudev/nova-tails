# Master Asset Architecture v0.1 — Acceptance Criteria

The design contract may be merged as an accepted **architecture baseline** when:

- responsibilities and authority boundaries are internally consistent;
- structured reference instance matches the minimal schema;
- at least two adapter manifests point to the same identity revision;
- dependency-change semantics are understandable;
- no unvalidated character/product/manufacturing claim is promoted to canon;
- follow-up artifact/physical proofs are explicitly tracked.

Merge does **not** mean:
- NT-CHAR-001 is production canon;
- cross-output leverage has market validation;
- print adapter is manufacturable;
- a game or print product has been selected.

Scaling the architecture to a roster has a stricter gate: actual cross-output artifact proofs must pass first.
