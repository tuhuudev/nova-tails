# NT-001 — Golden Character Vertical Slice v0.1

**Status:** PROTOTYPE / CANDIDATE
**Goal:** validate the complete NOVA TAILS character-to-output architecture before canonizing NT-001 or scaling the character library.

## 0. Definition of Done

Phase 1 is complete only when one coherent NT-001 lineage survives:

1. structured identity and Visual DNA;
2. Stage 1 base design;
3. Stage 2 and Stage 3 evolution continuity;
4. production reference/turnaround;
5. multi-pose consistency test;
6. 2D → 3D interpretation;
7. color/part separation suitable for an A1 Mini prototype strategy;
8. collectible, card/game and content representation tests;
9. review findings and architecture corrections.

Passing Phase 1 does NOT automatically canonize all generated lore, stats, names, abilities or visuals.

## 2. Stage 1 Visual DNA

### Silhouette
Compact quadruped. Oversized upright triangular ears dominate the upper silhouette. A large split flame-shaped tail dominates the rear silhouette. Head is proportionally large; legs/body are short and compact.

### Signature features
1. `EAR_SHAPE` — oversized triangular ears with layered flame-like internal shape language — weight 0.8 — LOCKED.
2. `FOREHEAD_MARK` — centered vertical diamond marking — weight 0.9 — LOCKED.
3. `TAIL_SPLIT` — recognizable split flame-shaped tail — weight 0.9 — LOCKED.

### Proportion target
- head: large/cute Stage-1 ratio;
- muzzle: short;
- torso: compact;
- legs: short but structurally readable for 3D;
- paws: enlarged enough to support physical figure stability;
- ears: large but must later pass thickness/center-of-mass review;
- tail: visually large but attachment strategy must be validated.

### Trait rules
LOCKED: ear silhouette, forehead diamond identity, split-tail identity.
EVOLVABLE: body size, pattern complexity, flame intensity, ear internal complexity, tail volume.
OPTIONAL: horns/crest/armor-like natural forms only if lineage identity remains clear.
FORBIDDEN: wings in current lineage; replacing split tail with a generic single tail; removing forehead identity mark.

## 3. Color & Material System

Current concept palette is candidate evidence, not final canon.

Role-based palette:
- base fur: cream/off-white;
- primary warm marking: ember orange;
- secondary warm transition: sunset gold/light orange;
- deep accent: flame red;
- eyes: amber/gold;
- elemental FX: orange/yellow emissive interpretation.

Production rule: separate `body material color` from `element FX color`. A rendered glow cannot be assumed printable.

For later physical prototype, target a minimal practical material palette before adding decorative paint requirements.

## 4. Evolution Family Prototype

Evolution is a lineage test, not three independent character prompts.

### Stage 1 — working label: Spark Pup
Intent: cute, compact, approachable, energetic.
Must preserve all three signature features.

### Stage 2 — working label: Blaze Runner
Intent: agile/adventurous transition.
Expected changes:
- longer legs and torso;
- more balanced head/body ratio;
- increased tail/flame volume;
- stronger directional markings;
- signature ears/forehead/tail remain immediately recognizable.

Do not introduce wings. Avoid heavy armor or unrelated motifs.

### Stage 3 — working label: Nova Guardian
Intent: mature/powerful/protective.
Expected changes:
- stronger chest/limb structure;
- mature facial proportions;
- higher flame complexity/intensity;
- optional crest/horn-like development may be tested but must not replace ear identity;
- split-tail lineage remains readable.

### Evolution acceptance
Side-by-side silhouettes at thumbnail size should read as one lineage. Stage 2 must visually bridge Stage 1 and Stage 3 rather than behaving as a disposable middle form.

## 6. Consistency Test Matrix

Generate/test the same Stage-1 identity in at least these situations:

| Test | Purpose |
|---|---|
| Neutral standing | baseline |
| Sitting | body proportion preservation |
| Running | tail/ear behavior |
| Jump/action | silhouette under deformation |
| Happy expression | facial identity |
| Determined expression | facial range |
| Front close-up | forehead/ear consistency |
| Rear/3-4 rear | tail and back markings |
| Small thumbnail | recognition |
| Simple environment render | identity under lighting/background change |

Review each output for signature feature preservation, color-role continuity, forbidden traits and accidental redesign.

No automated numeric threshold is canon in v0.1. Record qualitative pass/fail and concrete failure reasons first.

## 7. 3D Interpretation Requirements

The first 3D model is a feasibility prototype, not a production sculpt.

### Required geometry groups
- head;
- left/right ears;
- eye inserts or eye-color solution;
- torso/body;
- front limbs;
- rear limbs;
- tail root;
- tail flame lobes/sections where useful;
- optional markings/inlays only if practical;
- connectors.

### 2D → 3D questions
- Does the face still read as NT-001 without painterly lighting?
- Are ears structurally plausible?
- Can the tail support itself or require a keyed attachment/support?
- Are legs/paws thick enough for a small figure?
- Which flame shapes are geometry versus visual FX?
- Can the forehead diamond become paint, inset, or separate colored part?

---

## 8. A1 Mini Printable Prototype Strategy

Target: validate assembly and color separation on a Bambu Lab A1 Mini-class FDM workflow; exact slicer settings remain experimental until real geometry exists.

### Design-for-assembly principles
- avoid relying on glowing/translucent render FX;
- prefer broad keyed connections over fragile pins;
- hide seams along natural fur/marking boundaries where possible;
- avoid thin free-floating flame tips;
- orient split tail so it can be supported/assembled without destroying its signature silhouette;
- make feet/paws provide stable contact area;
- test ear thickness before final aesthetic lock.

### Prototype package
- source 3D master;
- print-adapted master;
- separated parts;
- STL/3MF exports only after geometry exists;
- assembly map;
- slicer/test notes;
- photos/notes from physical validation.

A generated exploded-view illustration is not manufacturability proof.

## 9. Output Validation

### Collectible figure
Test whether silhouette, face, forehead mark and tail remain recognizable without environmental VFX.

### Card/game representation
Create a compact portrait/full-body treatment and verify NT-001 reads at small size. Game mechanics remain candidate data.

### Animation/content
Test one short action beat: idle → notice spark → playful movement/action → return to readable pose. Purpose is motion/silhouette validation, not content automation.

### Social/marketing image
Test one clean hero image from the same approved reference. Do not create a separate visual identity for marketing.

---

## 10. Review Gates

### Gate A — Base Identity
Pass when Stage 1 has an agreed silhouette, 2–4 signature features and role-based palette.

### Gate B — Evolution
Pass when Stages 1/2/3 read as one family and locked traits survive.

### Gate C — Reference Consistency
Pass when required views and test poses do not repeatedly redesign the character.

### Gate D — 3D Feasibility
Pass when a plausible model/part strategy exists without deleting recognition-critical features.

### Gate E — Physical Feasibility
Pass only after a real print/assembly test is documented. Rendered exploded views cannot pass this gate.

### Gate F — Cross-output Identity
Pass when figure/card/content representations remain recognizably the same character.
